# 订单与售后自动处理工作台设计

## 目标与边界

把订单异常识别、人工复核、售后工单协同与外部动作打卡放入同一独立工作台，展示“发现风险—分派—人工处理—可追溯留痕”的闭环。

本 PoC 使用模拟、脱敏订单快照。系统不写入真实订单、退款、补发或物流平台；所有真实外部操作均由获授权人员在原业务系统完成并回填。

## 页面结构

### 订单与售后工作台

- 顶部 KPI：待人工复核、SLA 临期、高风险订单、待外部执行打卡。
- 左侧异常订单队列：按优先级、渠道、状态、负责人筛选；列表展示订单标识、规则命中、建议动作和 SLA。
- 右侧售后工单队列：退款、补发、咨询三类工单；展示当前环节、负责人、截止时间和最新说明。
- 详情抽屉/面板：展示脱敏订单核心字段、规则命中的判定依据、脱敏用户历史工单统计、建议动作、处理说明和审计历史。

### 规则与导入页

- 本地 CSV 或未来官方/客户授权 API 适配器的快照导入。
- 订单规则、售后 SLA 和负责人规则均标注版本；规则变更由主管确认后生效。
- 导入失败显示行号与原因；不含真实账号密码或可识别个人信息。
- 订单异常识别规则与售后 SLA/分派规则分为两个独立规则库，各自维护版本、审批和回滚记录。

## 首期模拟规则

| 类型 | 条件 | 优先级 | 系统建议 |
| --- | --- | --- | --- |
| 价格/优惠冲突 | 实付金额与优惠规则或活动价不一致 | 高 | 进入人工复核，不自动取消订单 |
| 库存/地址校验失败 | 库存不足、收货区域不可达或地址字段异常 | 中 | 请求仓配确认，必要时人工联系客户 |
| 疑似风险订单 | 同一脱敏标识短期重复下单等可疑信号 | 高 | 标记待复核，不自动认定欺诈 |
| 退款工单 | 用户申请退款 | 中 | 核验履约与售后规则后人工处理 |
| 补发工单 | 破损、漏发或物流异常 | 高 | 复核证据后创建补发建议 |
| 咨询工单 | 物流、商品或售后进度咨询 | 低 | 分派人工客服并保留回复说明 |

SLA 从规则命中或工单创建时刻开始计时：高风险 24 小时未处理置顶标红并通知主管；中风险 72 小时触发提醒；低风险咨询工单为 48 小时。各类型 SLA 均可由主管在规则库中配置。

同一订单在同一快照批次中命中多条异常规则时，合并为一条待办，按最高优先级排序并在详情中保留全部命中原因。未命中任何异常规则的订单不会进入待处理队列。

首期支持演示自动分派：按渠道、工单类型或品类分派给预设负责人，并可使用轮询规则；主管始终可以手动调整负责人。

## 状态与权限

订单异常使用状态机：`待复核 → 处理中 → 已解决/已忽略 → 外部执行已打卡`。

售后工单使用独立状态机：`待处理 → 处理中 → 待外部执行/待用户反馈 → 已关闭`。退款或补发工单在外部执行信息完成打卡后才能关闭；咨询工单需记录人工回复摘要后才能关闭。

- 运营专员：只能认领和处理分配给自己的项目，需填写处理说明。
- 运营主管：可分派负责人、调整优先级、重开已关闭项目、确认规则变更。
- 管理层：只读查看汇总、队列和导出结果，无处理按钮。

低风险咨询工单可批量认领或批量标记已处理；高风险订单、退款和补发工单必须逐条人工审核，禁止批量关闭。

每次状态流转记录操作者角色、时间和处理说明。外部执行凭证编号指外部系统人工操作后生成的唯一标识，例如退款流水号、补发物流单号或原平台售后处理单号。打卡字段按工单类型强制区分：退款填写实际退款金额与流水号；补发填写物流单号与补发商品规格；咨询填写回复内容摘要。打卡只表示已在外部系统由人工完成，不表示系统发起了真实平台操作。

## 数据与模块边界

- `domain/orderService.ts`：订单异常、售后工单、状态和审计记录的数据模型。
- `services/orderRules.ts`：规则命中、优先级和 SLA 计算；纯函数、可单测。
- `services/orderWorkflow.ts`：权限校验、状态流转、分派与外部打卡。
- `data/orderServiceFixtures.ts`：覆盖三类订单异常和三类售后工单的脱敏模拟数据。
- `pages/OrderServiceWorkbenchPage.tsx`：双队列、详情、处理表单和角色差异。
- `pages/OrderRulesPage.tsx`：规则版本、导入说明与降级边界。

## 降级与合规

数据接入仅支持官方 API、客户本地授权导入或明确标注的模拟快照。降级状态分为：正常（授权接口或最新导入）、轻度降级（复用最近 24 小时成功快照）、完全降级（切换内置模拟数据）。接入失败时显示数据来源、更新时间和降级状态；缺失数据绝不按 0 展示。

订单导出默认脱敏：姓名仅保留姓氏、手机号中间四位打码、地址仅保留省市层级、支付信息完全隐藏。导入时检测未脱敏敏感字段，命中即拦截并返回行号与原因。

## 验收与测试

- 全流程闭环：三类订单异常与三类售后工单均可在模拟数据中展示，且可完成对应状态机的闭环。
- 规则识别：同单多规则命中可合并；正常订单不进入待办队列；规则命中原因可追溯。
- 角色权限：角色切换真实改变可执行操作，禁止越权处理和越权批量关闭。
- SLA 机制：高风险 24 小时、中风险 72 小时、咨询 48 小时提醒可演示。
- 审计留痕：分派、处理说明、状态流转和按场景差异化的外部执行打卡均有历史记录。
- 合规脱敏：导入会拦截未脱敏敏感字段，导出默认隐藏敏感信息；三档降级状态明确可见。
- 测试覆盖：单元测试覆盖规则识别、权限和状态流转；页面测试覆盖完整处理路径；完整回归、生产构建和浏览器端到端检查均通过后才交付。

该模块与公域需求雷达、竞品价格工作台复用同一套角色权限、快照导入、降级容错和审计规范，构成覆盖获客、定价和履约的电商运营驾驶舱作品集。
