# 订单与售后自动处理工作台设计

## 目标与边界

把订单异常识别、人工复核、售后工单协同与外部动作打卡放入同一独立工作台，展示“发现风险—分派—人工处理—可追溯留痕”的闭环。

本 PoC 使用模拟、脱敏订单快照。系统不写入真实订单、退款、补发或物流平台；所有真实外部操作均由获授权人员在原业务系统完成并回填。

## 页面结构

### 订单与售后工作台

- 顶部 KPI：待人工复核、SLA 临期、高风险订单、待外部执行打卡。
- 左侧异常订单队列：按优先级、渠道、状态、负责人筛选；列表展示订单标识、规则命中、建议动作和 SLA。
- 右侧售后工单队列：退款、补发、咨询三类工单；展示当前环节、负责人、截止时间和最新说明。
- 详情抽屉/面板：展示脱敏订单或工单上下文、规则命中、建议动作、处理说明和审计历史。

### 规则与导入页

- 本地 CSV 或未来官方/客户授权 API 适配器的快照导入。
- 订单规则、售后 SLA 和负责人规则均标注版本；规则变更由主管确认后生效。
- 导入失败显示行号与原因；不含真实账号密码或可识别个人信息。

## 首期模拟规则

| 类型 | 条件 | 优先级 | 系统建议 |
| --- | --- | --- | --- |
| 价格/优惠冲突 | 实付金额与优惠规则或活动价不一致 | 高 | 进入人工复核，不自动取消订单 |
| 库存/地址校验失败 | 库存不足、收货区域不可达或地址字段异常 | 中 | 请求仓配确认，必要时人工联系客户 |
| 疑似风险订单 | 同一脱敏标识短期重复下单等可疑信号 | 高 | 标记待复核，不自动认定欺诈 |
| 退款工单 | 用户申请退款 | 中 | 核验履约与售后规则后人工处理 |
| 补发工单 | 破损、漏发或物流异常 | 高 | 复核证据后创建补发建议 |
| 咨询工单 | 物流、商品或售后进度咨询 | 低 | 分派人工客服并保留回复说明 |

## 状态与权限

统一状态为：`待复核 → 处理中 → 已解决/已忽略 → 外部执行已打卡`。

- 运营专员：只能认领和处理分配给自己的项目，需填写处理说明。
- 运营主管：可分派负责人、调整优先级、重开已关闭项目、确认规则变更。
- 管理层：只读查看汇总、队列和导出结果，无处理按钮。

每次状态流转记录操作者角色、时间、处理说明和可选的外部执行凭证编号。打卡只表示已在外部系统由人工完成，不表示系统发起了真实平台操作。

## 数据与模块边界

- `domain/orderService.ts`：订单异常、售后工单、状态和审计记录的数据模型。
- `services/orderRules.ts`：规则命中、优先级和 SLA 计算；纯函数、可单测。
- `services/orderWorkflow.ts`：权限校验、状态流转、分派与外部打卡。
- `data/orderServiceFixtures.ts`：覆盖三类订单异常和三类售后工单的脱敏模拟数据。
- `pages/OrderServiceWorkbenchPage.tsx`：双队列、详情、处理表单和角色差异。
- `pages/OrderRulesPage.tsx`：规则版本、导入说明与降级边界。

## 降级与合规

数据接入仅支持官方 API、客户本地授权导入或明确标注的模拟快照。接入失败时保留最近一次成功快照，并显示数据来源、更新时间和降级状态；缺失数据绝不按 0 展示。

订单导出默认脱敏，不包含姓名、完整手机号、完整地址或支付凭证。敏感字段校验失败时拒绝导入并说明原因。

## 验收与测试

- 三类订单异常与三类售后工单均可在模拟数据中展示。
- 角色切换真实改变可执行操作。
- 处理说明、分派、状态流转和外部执行打卡均有审计历史。
- 高风险 24 小时、普通风险 72 小时的 SLA 提醒可演示。
- 单元测试覆盖规则识别、权限和状态流转；页面测试覆盖完整处理路径。
- 完整回归测试、生产构建和浏览器端到端检查均通过后才交付。
