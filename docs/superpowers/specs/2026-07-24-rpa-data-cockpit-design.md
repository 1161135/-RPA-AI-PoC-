# 智营 RPA 数据驾驶舱 PoC：产品与技术设计

## 1. 目标与产品定位

“智营 RPA 数据驾驶舱”是面向电商运营团队的内部网页 PoC。它验证一名 RPA 工程师能从 0 到 1 建立“数据接入、统一指标、经营洞察、异常闭环、自动化运行监控、Power BI 输出”的最小运营自动化底座。

本项目使用完全模拟的数据，不声称已接入健元药业或任何公司的真实系统。健元药业仅作为医药行业演示配置；通用产品能力可复用于零售、品牌电商等场景。

## 2. 用户与核心问题

| 用户 | 工作目标 | 当前问题 | PoC 解决方式 |
| --- | --- | --- | --- |
| 电商运营专员（主用户） | 制作日报、发现并处理经营异常 | 多平台导表、手工汇总、异常发现晚 | 自动汇总、统一日报、异常待办和处理留痕 |
| 运营主管 | 比较渠道和商品表现、分派优先级 | 指标口径不一致、无法快速定位问题 | 渠道/SKU 对比、异常分级和建议动作 |
| 管理层 | 查看经营结论、自动化价值 | 只有结果没有过程与效率依据 | 聚合 KPI、运行摘要、模拟节省工时口径 |

## 3. MVP 范围

### 3.1 第一期开做

- 支持淘宝/天猫、京东、抖音三渠道的模拟数据。
- 经营总览：GMV、支付订单、支付转化率、客单价及趋势。
- 每日经营日报：昨日结论、渠道贡献、异常摘要、建议动作。
- 商品分析：SKU 销售、转化和库存风险。
- 异常中心：销售/转化/库存/数据采集异常；状态为待处理、处理中、已处理。
- 自动化任务：采集任务成功率、最后运行、失败任务、日志和模拟节省工时。
- 数据接入与行业规则：展示模拟数据、未来 API/ERP/RPA 导入适配器和医药行业规则包。
- CSV/Excel 格式的统一数据集输出，作为 Power BI 第一阶段数据源。

### 3.2 明确不做

- 真实平台登录、爬取、写入、调价、退款或 ERP/WMS 写回。
- 抖音评论自动回复、私信、加粉、真实用户信息采集。
- 真实 Power BI 嵌入和企业授权配置。
- 自动处理异常；系统只提供规则识别、建议动作和人工确认留痕。
- 深度移动端产品、预测模型和低代码插件配置平台。

### 3.3 二期规划（不属于 PoC 交付）

- 经合规、平台授权和人工审核验证后的抖音评论线索识别、待审核回复和人工跟进工作台。
- 真实 Power BI 嵌入、企业网关、计划刷新和角色授权。
- 预测模型、低代码配置和移动端深度适配。

抖音运营自动化与用户信息采集均不包含在 PoC 中；PoC 仅以抖音作为经营数据渠道。二期是否启动取决于平台权限、个人信息授权和医药合规审查。

## 4. 页面与交互

### 4.1 全局规则

- 顶部全局筛选：昨日、近 7 天、本月、自定义日期范围；渠道多选。
- 始终显示数据更新时间、数据来源和“模拟数据”标识。
- PoC 的数据刷新为每日 08:30 定时模拟刷新；“昨日”视图默认展示截至前一日 23:59:59 的经营数据。页面提供手动刷新按钮以重放模拟任务。
- 采集失败时保留最近一次成功数据，显示失败提示，绝不将缺失数据视为零。
- 角色视图以切换器模拟：运营专员、运营主管、管理层；PoC 不实现真实登录。

| 角色 | 可查看 | 可操作 |
| --- | --- | --- |
| 运营专员 | 全部页面、异常详情、任务日志 | 导出当前筛选数据；将异常认领/处理中/已解决/已忽略；填写处理说明 |
| 运营主管 | 全部页面、全渠道与全部异常 | 分配负责人；调整异常优先级；关闭或重新打开异常；导出当前筛选数据 |
| 管理层 | 总览、日报、聚合商品/渠道结论、ROI 摘要 | 仅筛选、查看和导出汇总日报；不能修改异常或任务状态 |

### 4.2 页面清单

| 页面 | 内容 | 主操作 |
| --- | --- | --- |
| 经营总览 | 经营 KPI、趋势、渠道贡献、异常摘要、运行摘要 | 选择时间/渠道、打开异常、导出日报 |
| 每日经营日报 | 昨日发生什么、渠道表现、重点变化、建议动作 | 导出统一数据集 |
| 商品分析 | SKU 表现、库存天数、渠道拆分 | 按 SKU/渠道筛选，打开异常 |
| 异常中心 | 严重级别、指标变化、原因、建议、负责人、状态、日志 | 处理状态流转、指定负责人 |
| 自动化任务 | 任务状态、成功率、执行时长、失败原因、人工基线 | 查看日志与刷新状态 |
| 数据接入与行业规则 | 数据源状态、字段映射说明、行业规则包 | 查看未来接入说明 |

导出默认遵循当前时间、渠道与角色筛选条件。PoC 提供 CSV 格式的“统一事实数据集”和“日报摘要”两种固定字段导出；字段字典随统一事实数据集一并下载。所有导出默认不含姓名、手机号、地址、账号标识等可识别个人信息。

异常状态机：新异常默认为“待处理”；运营专员认领后变为“处理中”；提交处理说明后可变为“已解决”或“已忽略”；运营主管可重新打开“已解决/已忽略”的异常。每次流转必须记录操作者、时间和说明。

## 5. 统一指标与异常规则

### 5.1 指标口径

- GMV：选定周期内已支付订单金额之和，退款单独展示且不混入 GMV。
- 支付订单：支付成功订单数。
- 支付转化率：支付订单数 / 访问量。
- 客单价：GMV / 支付订单数。
- 库存可售天数：可用库存 / 近 7 日平均日销量。
- 模拟节省工时：成功的自动化任务次数 × 该任务的标准人工耗时（分钟）÷ 60。首页同时展示任务名称、人工基线、自动化耗时和计算结果；所有结果标注“模拟测算”，不得表述为实际节省人力或成本。

### 5.2 首期异常规则

| 类型 | 规则 | 级别 | 建议动作 |
| --- | --- | --- | --- |
| 转化异常 | 当日转化率较近 7 日均值下降 15% 及以上 | 高 | 检查商品页、价格、投流和渠道内容 |
| 销量异常 | 当日支付订单较近 7 日均值下降 20% 及以上 | 高 | 检查库存、活动、流量及平台任务状态 |
| 库存风险 | 可售天数小于 3 天 | 高 | 复核库存并创建补货跟进 |
| 采集失败 | 数据适配器最近一次任务失败 | 中 | 保留上次成功快照，排查运行日志 |
| 价格异常 | 当前价格与目标价差超过 10% | 中 | 人工核实竞品及平台活动，不自动改价 |
| 销量异常上升 | 当日支付订单较近 7 日均值上升 30% 及以上 | 中 | 核查活动、库存承载与异常订单风险 |
| 转化异常上升 | 当日转化率较近 7 日均值上升 25% 及以上 | 中 | 核查价格配置、流量来源与异常订单风险 |
| 医药合规异常（行业规则包） | 处方药人工复核超时，或模拟商品素材命中敏感宣传词 | 高 | 阻断对外发布演示，通知合规负责人复核；不自动下架真实商品 |

异常默认按渠道分配：淘宝/天猫、京东、抖音各有一名模拟渠道负责人；库存与合规异常默认分配给“供应链专员”和“合规专员”。运营主管可重新指定负责人。

## 6. 系统架构

```text
模拟 CSV/JSON → 数据适配器接口 → 统一事实数据与维表
                                     ↓
                         指标计算服务 + 规则异常引擎
                                     ↓
      网页驾驶舱 ← 任务日志与状态 ← 自动化任务模拟器 → CSV/Excel 输出 → Power BI
```

代码以可替换边界组织：

- `adapters`：每个渠道独立适配器；当前读取模拟文件，未来可替换 API、ERP/WMS 导出或 RPA 输出。
- `domain`：渠道、SKU、订单汇总、任务、异常及行业规则等稳定领域模型。
- `services`：指标计算、异常检测、日报摘要、ROI 测算和数据导出。
- `ui`：页面、筛选器、图表、异常详情和角色视图。

PoC 阶段的 Power BI 交付仅为统一 CSV 数据集、字段字典和连接说明；不嵌入报表、不配置网关、不生成未经 Power BI Desktop 验证的 `.pbit` 模板。正式上线阶段才在取得企业账号、数据模型、Power BI Desktop 版本和授权后实施嵌入、网关、刷新频率与权限配置。

## 7. 视觉与信息层级

首页必须按以下顺序呈现：

1. 时间/渠道筛选、数据刷新状态和模拟数据标识。
2. 经营 KPI：GMV、订单、转化率、客单价。
3. 可读趋势与渠道贡献：带坐标轴、单位、图例、精确数值和金额/占比。
4. 可点击的待处理异常。
5. 独立的自动化运行摘要：成功率、失败任务、任务耗时和模拟节省工时。

异常状态同时使用文字、图标和颜色。首页不展示设计确认控件、行业说明长文或拟真企业权限信息。

## 8. 成本、风险与合规

本地 PoC 不依赖付费 API、云服务器、真实数据或企业账号。后续生产成本取决于平台 API 权限、Power BI 许可/网关、数据库与服务器、RPA 许可、模型调用量和运维人力。

主要风险：

- 平台接口/账号授权和数据更新频率不可假设。
- 跨平台字段及指标口径必须由业务确认。
- 医药内容和个人信息处理须遵守企业合规与平台规则。
- 真实采集失败应降级至最近成功快照，并产生可追溯日志。
- PoC 阶段不采集、处理或展示真实用户个人信息；全部数据为模拟脱敏数据，导出数据集默认不含可识别个人信息字段。

## 9. 验收标准

- 本地可启动并完整演示三渠道的数据筛选和图表联动。
- 所有图表有明确口径、时间轴/数值单位/图例或数值标签。
- 可模拟采集失败、触发异常、查看详情并完成处理状态流转。
- 可导出统一数据集，字段与数据字典可被 Power BI 使用。
- “节省工时”显示计算公式和模拟测算标识。
- 全部数据、ROI 和集成状态不误导为真实公司生产数据。

## 10. 多智能体协作边界

- Codex 负责产品裁决、主实现、集成和验收。
- Claude Code 负责独立代码与架构审查。
- Hermes 或 Reasonix/DeepSeek 负责 PRD 反驳审查、测试用例和异常规则评审。
- 外部智能体默认只读评审；只有经过 Codex 收口的单一任务才能写入，避免并发修改冲突。
